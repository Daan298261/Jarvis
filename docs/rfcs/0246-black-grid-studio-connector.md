## Problem

Verified on `development` @ `e1a0e7d6`.

1. **Only the old studio is reachable.** `tools/blackgrid_studio.py::BlackGridStudioTool` drives a local ComfyUI HR Endless sampler through `studio/blackgrid_runtime.py` (port 8188, `BlackGridSettings` in `config.py`). It cannot reach the new Black Grid Multimedia Studio (local FastAPI on `127.0.0.1:8745`), which has a story bible, durable pipeline runs, streaming book ingest, Wan2.2 clip generation, review and a final stitch (BGM #32-#34).
2. **The tool is nearly unreachable in the live path.** The live loop uses `agent/tool_exposure.py` (`tool_names_for`, `schemas_for`). Its `CLASS_TOOLS` and `CAPABILITY_ALIASES` do not mention `blackgrid_studio`, and `agent/tool_retrieval.py::_SEARCH_TERMS` has no entry for it. Only the older `tools/exposure.py::TASK_TOOL_SETS` lists it (used by `agent/local_harness.py`). In practice the model reaches it only by calling `request_tools` with the exact name.
3. **No policy for studio actions.** `policy/reversibility.py::resolve_action_effect` knows nothing about `blackgrid_studio`, so every action falls into the generic medium-risk path. A multi-hour render and a read look the same to the gate.
4. **ANZU and the studio fight for 16 GB.** The studio's Wan2.2 clip runs need almost all of a 16 GB card. ANZU's models (front and worker seats, LM Studio or llama.cpp instances loaded by ANZU) stay resident, and nothing on `development` checks whether another application is rendering before a model is loaded by `InferenceManager.load`, by `FrontRuntime.ensure_started`, or by the direct warms that bypass both (`ollama_runtime.ensure_local_ollama` with its HTTP warm, `gpu_prefer.ensure_ollama_gpu`, `gpu_prefer.ensure_lmstudio_gpu`, `lmstudio_server.ensure_local_lmstudio`). The first symptom is a CUDA out-of-memory error halfway through a long render.
5. **The studio cannot say "the GPU is busy".** At the traced heads there is no endpoint that reports it. Runs are listed **per project** (`GET /api/projects/{project_id}/pipeline/runs`), and the legacy JSON-clip flow's jobs (`GET /api/jobs/{job_id}`, kinds `generate`, `video`, `image`, `stitch`) have no list endpoint at all. Run status alone is also the wrong signal: PG confirms a **paused** run still holds the Wan weights today, and a later Pause may release them. That is a studio-side gap (BGM-P1, with the fields PG named: `wan_loaded`, `active_run`, `paused`, `vram_mb`).

## Decision

Ship **one RFC with five implement slices (S1-S5)**, one named model per slice, fast mode off, plus **two studio-side PRs** that belong to the BGM repo and PG's review.

```
owner / model turn ─► agent/tool_exposure.py (alias + retrieval, S2) ─► ToolRegistry.execute("blackgrid_studio", action="studio_*")
        │                                   │
        │                                   ├─ gate: policy.reversibility.resolve_action_effect (new branch, S2) ─► ApprovalGrant for expensive/destructive actions (RFC-0031/0110)
        │                                   └─ BgmClient (S1, loopback only, fixtures-conformant) ─► http://127.0.0.1:8745/api/...
        │
        └─ before ANZU loads ANY model: StudioGpuGate.check (S3) ─► BGM-P1 GET /api/gpu/status (keys on wan_loaded / active_run / ingest_llm.loaded)
              busy ─► defer the load with a visible reason (explicit owner Load: refused, 409)
              free / studio not running ─► load as today
        run starts (seen by poll, or started through this tool) ─► verified release of ANZU-loaded models (#686 T3 path) ─► hold + visible reason
        run ends ─► hold cleared ─► respawn on demand by the next owner turn (`keep_warm` true: one BACKGROUND respawn of the released seats via RFC-0225 `prepare_engine_for`, skipped when `manually_unloaded` is set or the owner pressed Unload during the hold)
```

**One tool path, not a parallel one.** The connector is extra actions on the existing `blackgrid_studio` tool (same registry entry, same `ToolRegistry.execute`, same gate, same exposure code). There is no new tool class, no MCP server and no second HTTP layer.

| Term | Meaning |
| --- | --- |
| **Studio** | Black Grid Multimedia Studio, the BGM repo's `studio/backend` FastAPI app. |
| **Run** | One `pipeline_runs` row (`RunOut`): stage `clip_import`, `ingest`, `generate` or `stitch`; status `running`, `paused`, `completed`, `failed`. |
| **Studio hold** | The state in which ANZU has no ANZU-loaded model resident and loads none because BGM-P1 says the GPU is busy (`wan_loaded`, a running `generate` run, or the studio's own ingest model loaded). |

| **Background path / owner turn** | #686's terms (section "Load origin: owner turn vs background"). | **ANZU-loaded model** | A model ANZU started or loaded itself (front/worker seats, ANZU-managed llama.cpp, LM Studio or Ollama instances ANZU loaded). Models the owner loaded in another program are not ANZU-loaded. This is the same boundary RFC-0244, RFC-0228 and RFC-0245 use. |

`GpuStatus` (BGM-P1, from PG's workers; **the four field names `wan_loaded`, `active_run`, `paused`, `vram_mb` are PG's, the rest of the shape is proposed and PG's PR sets it**): `{"contract_version": 1, "wan_loaded": bool, "active_run": {"project_id", "run_id", "stage", "status": "running|paused", "cursor", "total"} | null, "paused": bool, "vram_mb": int, "ingest_llm": {"endpoint", "model", "loaded": bool}, "stitch_uses_gpu": false, "checked_at": iso}`.

**The gate's busy rule (normative).** `busy = wan_loaded OR (active_run.stage == "generate" AND active_run.status == "running") OR ingest_llm.loaded`. It keys on `wan_loaded` and `active_run`, **never on run state alone**: a `paused` run with `wan_loaded == true` is busy (PG: a paused run still holds Wan today), and a `paused` run with `wan_loaded == false` is **free**, so on the day a later BGM Pause releases Wan, ANZU frees the hold on its next poll with no ANZU change. A running `generate` run that has not loaded Wan yet (lazy load) is busy because it is about to. `ingest` is busy only while its LLM (`ingest_llm`, `bgm-ingest-9b` in Ollama) is loaded; `stitch` is CPU ffmpeg (libx264) and never holds the GPU, which P1 states as `stitch_uses_gpu: false` (any other value is a `StudioContractMismatch`). `vram_mb` is shown in the hold text and never used to decide. ANZU never reads run lists for this.

**Stage rules the connector relies on** (from `GenerateStage` / `StitchStage` / `PipelineRunner`):
- `generate` renders with Wan2.2 TI2V-5B when `GenerationConfig.video_backend == "wan"` (default); `video_backend == "ffmpeg"` is the no-GPU fallback (then `wan_loaded` stays false). `ingest` calls the studio's LLM, which PG confirms is **`bgm-ingest-9b` in Ollama** (not LM Studio, not ANZU's 9B; the PR text said the default `Settings.llm_base_url` is LM Studio, superseded by PG's answer; P1 exposes the real endpoint and model). `stitch` is CPU ffmpeg (libx264) and never holds the GPU (C6).
- One active (running or paused) run per project (`pipeline_one_active` unique index), so a second start answers 409 (`BibleConflict`).
- `stitch` needs every non-orphaned prompt approved with a take (`StitchStage.prepare`); readiness is `GET .../movie`.
- **Do not use** the legacy JSON-flow routes (`POST /api/projects/{pid}/stitch`, `.../clips/{cid}/generate`, `GET /api/jobs/{job_id}`). The connector's `studio_start_stitch` means the **pipeline stage** `stitch` via `POST .../pipeline/runs`, never the legacy `POST /api/projects/{pid}/stitch` that has the same word in its path (C7).

## 2. The connector client (S1)

`backend/app/studio/bgm_client.py::BgmClient` is the only code that talks to the studio.

- **Loopback only, enforced twice.** `config.BlackGridSettings` gains `studio_api_enabled: bool = True` (**default on**: the connector is loopback only, Taco wants ANZU to call the studio, and when no studio is running the tool says so plainly; the field is a kill switch kept in `settings.json`, documented in `TOOLS.md`, and `false` makes every studio action answer "The Black Grid Studio connector is switched off in settings (studio_api_enabled)" with no network call and no watcher poll), `studio_api_url: str = "http://127.0.0.1:8745"`, and a Pydantic validator that rejects anything else. `BgmClient.__init__` re-validates, so a settings file edited by hand cannot bypass it. Accepted hosts are exactly `127.0.0.1`, `::1` and `localhost` (normalised to `127.0.0.1`), scheme `http` only, no userinfo, no path other than empty or `/`. It deliberately does **not** reuse `tools/safety.py::is_owner_local_host`, which also accepts RFC1918 and `.local` hosts.
- **No detours.** `httpx.AsyncClient(follow_redirects=False, trust_env=False, timeout=...)`, so a proxy variable or a redirect cannot carry a call off the loopback interface. A 3xx answer is an error.
- **Timeouts.** Read calls 5 s, writes 15 s, the upload streams the file in 1 MiB blocks with a 300 s total. Studio steps run on the studio's own thread, so these calls never wait for a render.
- **Studio not running is a result, not an exception.** Connection refused (and only that) returns `StudioNotRunning` and the tool answers `{"studio": "not_running", "detail": "Black Grid Multimedia Studio is not running on 127.0.0.1:8745. Start it from its folder (studio/start.ps1) and ask again."}`. Timeouts, 5xx and malformed bodies are different, named errors (`StudioTimeout`, `StudioError`, `StudioContractMismatch`) with the studio's own detail text.
- **Contract conformance.** Every response is parsed by the mirrored Pydantic models with `extra="ignore"` for new optional fields but **required fields missing or a wrong type raises `StudioContractMismatch("<endpoint>: <field>")`**; the tool shows it verbatim. `GET /api/contract` is read once per session and **validated before any write and before any upload byte is sent** (see *Identity, privacy and untrusted text*): `contract_version` must be `1` (the version this RFC was written for; CI pins the whole answer in `tests/fixtures/bgm/contract.json`, S5), and every endpoint of the client registry must be listed in its `endpoints`. Otherwise every action but `studio_status` answers "studio contract version N is not supported by this ANZU" or names the missing endpoint.
- **Recorded fixtures.** `scripts/record_bgm_fixtures.py` (run locally by PG or on VRPC against a running studio; CI never starts a studio) calls each endpoint of §1 and writes `tests/fixtures/bgm/<endpoint-slug>.json` plus `tests/fixtures/bgm/manifest.json` (endpoint, method, BGM `main` description, recorded date). The conformance test replays them, so CI needs no studio for it.
- **Files stay in ANZU's policy.** `studio_upload_source` takes an absolute path that must resolve through `tools/safety.py::resolve_allowed_path` against `live_allowed_directories(...)` (the same allow-list the filesystem tool uses), and the extension is checked before any byte is read.

### Identity, privacy and untrusted text (S1 and S2)

ANZU sends file bytes and book text to whatever listens on `127.0.0.1:8745`, and everything the studio sends back is derived from a book the owner (or someone else) wrote. Three rules:

1. **The contract is validated before any upload (S1).** `BgmClient.upload_source` and every write call `ensure_contract()` first: `GET /api/contract` must succeed, `contract_version == 1`, and every endpoint ANZU uses must be listed (the same set S5 pins). A failure sends **no byte** and answers `StudioContractMismatch` (or `not_running`). This is the only identity check a loopback port can have today (BGM has no auth), so it runs once per session and again after any connection error.
2. **The ingest model's endpoint is shown and loopback-checked (S2).** `studio_start_ingest` and `studio_upload_source` read BGM-P1's `ingest_llm.endpoint` and `ingest_llm.model` (the gate's last snapshot, refreshed by the tool; no network call in the sync gate branch). The `studio_start_ingest` approval popup shows the model and the endpoint and says that the book text goes to it; the `studio_upload_source` result shows them. **A non-loopback endpoint (any host other than `127.0.0.1`, `::1`, `localhost`) refuses both actions**, and so does an unreadable `ingest_llm` (fail closed), with the plain text "The studio's ingest model points at <endpoint>, which is not on this PC; ANZU will not send a book there." The tool re-reads the endpoint after the grant and refuses if it differs from the one the popup showed, so the owner never approves a pair that changed.
3. **Studio-returned text is untrusted data (S2).** Every free-text field the studio returns (entity names and descriptions, prompt text, proposals, remarks, error `detail`) is wrapped by `studio/untrusted.py::fence_studio_text` before it enters `ToolResult.data`: a fixed delimiter block labelled as studio data, with any delimiter lookalike inside the text neutralised, and a one-line header that it is data from a book-derived record and never an instruction. ANZU-generated fields (ids, counts, statuses, run progress) are not fenced. Approval popups are built from ANZU's own fields (ids, counts, config) and never from studio text. (There is no shared tool-output fence in `backend/app` today, so S2 adds this one helper; it adds no new confirmation mechanism.)

## 4. The GPU gate (S3)

`backend/app/studio/gpu_gate.py::StudioGpuGate` is the only new moving part.

**What it reads.** `BgmClient.gpu_status()` (BGM-P1) and applies the busy rule of §1. Result classes: `free` (200, rule false), `busy` (200, rule true), `not_running` (connection refused), `unknown` (timeout, 5xx, malformed, contract mismatch). It never reads project run lists and never decides from run state alone.

**Where it checks: every place a model can start, not two.** Four kinds of site, all classified by one static test:

1. **The one load choke point, `InferenceManager._load_impl`** (#686's section "Load origin: owner turn vs background" explains why it is there: `_load_locked` wraps it and is its only caller, so `load`, `ensure_runtime`, `ensure_vision` and `release_vision` all reach it; a check in `load` or `_load_locked` would be bypassed by `ensure_*`). Its first statements are #686's mode and manual-unload/origin checks; S3 adds the studio-busy check **right after them, in the same function**, and nowhere in `load` or `_load_locked`.
2. **The front responder:** `inference/front_runtime.py::FrontRuntime.ensure_started` and `_start_local`, which do not go through the manager.
3. **The direct loaders and warms that bypass both** (they exist on `development` today; callers in parentheses):
   - `inference/ollama_runtime.py::ensure_local_ollama` (HTTP warm with `keep_alive: "24h"`; called from `main.py` startup, the `api/model.py` load route, `api/named_personas.py` (persona brain) and `inference/hotswap.py`),
   - `inference/gpu_prefer.py::ensure_ollama_gpu` (`keep_alive: "24h"`; called from `ensure_local_ollama`),
   - `inference/gpu_prefer.py::ensure_lmstudio_gpu` (`lms load` and the REST load; no caller on `development` today, guarded so a future caller cannot bypass the gate),
   - `inference/lmstudio_server.py::ensure_local_lmstudio` (`lms load`).
   Each calls the same check first, and the same manual-unload and origin check #686 specifies for direct-HTTP warms. Once #686's T3 has moved these call sites onto its single Ollama request helper and its LM Studio load helper, the check sits in those two helpers, and the calls in the four functions stay as a second, idempotent check. **KW owns the `keep_alive` values** (it removes the `"24h"`); S3 never edits a value.
4. **Keep-alive refresh, preload, `NINE_B_REWARM`, the `RUNNING_MODELS` poll and every other background path** reach a load only through kinds 1 to 3, so they are covered by the same checks and by #686's origin rule (they enter `background_scope()`).

`test_every_load_and_warm_site_is_classified_for_studio_hold_and_manual_unload` (static) scans `backend/app` for `MANAGER.load(`, `ensure_runtime(`, `ensure_vision(`, `ensure_local_ollama(`, `ensure_ollama_gpu(`, `ensure_lmstudio_gpu(`, `ensure_local_lmstudio(`, `"keep_alive"` payloads and `lms` / `"load"` CLI argument lists. Every hit must appear in the test's table with two columns, **studio hold** (guarded here, or "reaches kind 1 to 3 through a guarded caller") and **manual-unload / origin** (guarded by #686's rule), and an unclassified new site fails the test.

| Situation | Automatic load (chat turn, startup restore, `RUNNING_MODELS` autoload, persona brain, direct warm, keep-warm respawn) | Explicit owner Load (#686 T6 routes) |
| --- | --- | --- |
| `free` or `not_running` | proceeds as today | proceeds as today |
| `busy` | **deferred**: raises `StudioGpuBusy(RuntimeError)` with the reason text below (a direct warm returns `{"ok": false, "method": "studio-hold", "detail": <reason>}`); autoload branches that #686 already skips silently skip silently | **refused**: `POST /api/model/load` and the activate routes answer 409 with the same text; the owner can pause the run (`studio_run_control`) or wait. No silent override. |
| `unknown` | deferred with "Studio status could not be read; ANZU is waiting rather than risk the render." | **allowed** (only a confirmed busy status blocks an explicit owner action) |

Reason text (fixed, tested). Four variants, chosen by BGM-P1's `active_run` and `ingest_llm`:
- **Render** (`wan_loaded` or a running `generate` run): `BlackGrid Studio is rendering (project "<title>", clip <cursor>/<total>; about <vram_mb> MB of the GPU). ANZU's models stay unloaded so the render keeps the GPU. Ask again when it finishes, or pause the run.`
- **Paused but still holding Wan:** `BlackGrid Studio's run is paused but still holds the GPU (Wan is loaded).`
- **Ingesting** (`active_run.stage == "ingest"` and `status == "running"`, model loaded): `BlackGrid Studio is ingesting a book (its model bgm-ingest-9b is loaded). ANZU's models stay unloaded until it finishes.`
- **Idle resident ingest model** (`ingest_llm.loaded` and **no active run**): `BlackGrid Studio's ingest model bgm-ingest-9b is still loaded in Ollama and no run is active. ANZU will not touch it. Free it in Black Grid Studio, or run "ollama stop bgm-ingest-9b", and ask again.` (The model name in the text is P1's `ingest_llm.model`.) This variant names no run and gives the owner the exit, because ANZU may not unload the studio's model and the explicit Load answers 409 while it is resident.

Jev and Laya are CPU deciders and keep answering reflex turns during a hold; only generative turns see the reason.

**Unload on run start: one rule for every run stage that loads a model (`generate` and `ingest`).** Two triggers, one action, identical results:
- *Started through ANZU:* `studio_start_generation`, `studio_regenerate`, `studio_start_ingest`, and a `resume` of a `generate` or `ingest` run (the tool reads the run's stage at execution time; `stitch` and `clip_import` release nothing), after the grant and **before** the `POST`, calls `model_release.release_all_anzu_loaded` (#686 T3's verified release) for **every model in the ANZU ledger, front seat included** (`reason="studio_run"`). If the release is not verified (T3's own 409/502 result) or ANZU is mid-answer (`MANAGER._request_lease.exclusive()` not acquired), **the studio run is not started** and the tool says why. Nothing is half-started. For `ingest` and `generate` the tool also opens a **start hold** from the `POST` until BGM-P1 shows the run no longer `running`, or shows the model loaded (then the normal busy rule takes over), or 120 s pass with neither (the run failed to start); the start hold closes the gap before the studio lazily loads its model, so ANZU cannot load its own 9B in between.
- *Started from the studio's own UI:* a watcher polls BGM-P1 every `STUDIO_WATCH_INTERVAL_S = 10` while any ledger model is resident, backs off to `STUDIO_WATCH_BACKOFF_S = 60` while the studio is `not_running`, and polls nothing when no ledger model is resident, no hold is active, and `studio_api_enabled` is false. On `free → busy` (including `ingest_llm.loaded` turning true) it runs the same verified release.

A tool-started ingest and a UI-started ingest therefore both release ANZU's models and both hold, with the same text (`test_ingest_start_through_tool_and_through_ui_behave_identically`).

The release is #686's own unload-all path, `model_release.release_all_anzu_loaded` (the function behind `POST /api/model/unload-all`; S3 calls it, with `reason="studio_run"`, and has **no enumeration of its own**). It uses the **verified native path** only (LM Studio `loaded_instances` check, Ollama `/api/ps` check, managed process stop; #686 T3). A studio hold **does not set and does not clear** `manually_unloaded` (that flag means "stays unloaded until explicit Load" and belongs to an owner Unload, as #686's composition table says; only an explicit Load or an owner turn clears it), and it is **not** recorded as an idle unload (`engine_coexistence.idle_unloaded()` of RFC-0228); it is its own reason, `studio_hold`, reported only after the same verified evidence (R5). A hold clears itself. When an idle unload already released the models, run start finds nothing resident, releases nothing and still holds.

**Release, idle unload and `keep_alive` act on the ANZU ledger only, with the name guard as a backstop (CoS ruling, UX 5).** The target set of S3's release, of the keep-warm and idle-unload path, and of every `keep_alive` an ANZU request carries is the **ANZU ledger** (Terms): RFC-0225's `anzu_loads` section plus ANZU-managed processes. None of them enumerates `/api/ps` or `loaded_instances` and unloads what it finds, so **any model ANZU did not load is never touched, whatever its name**: the studio's `bgm-ingest-9b`, Taco's LM Studio 9B, or an unknown owner model. Layer two is `StudioModelGuard.is_studio_model(endpoint, model)`, which matches P1's `ingest_llm.endpoint` and `ingest_llm.model` **and** the constant name `bgm-ingest-9b` (so the skip holds even while the studio is down, P1 is unreadable, or a corrupt ledger lists it), and which #686's single Ollama request helper (`engine_requests.ollama_request`) already applies through its `bgm-ingest-9b` deny constant: **S3's guard reuses that constant and adds no second copy of the name**, and the release path calls the guard before sending anything. ANZU **never unloads `bgm-ingest-9b` and never sets `keep_alive` on it** (PG ruling 3, matching CoS's ruling to D2). If D2's path does not already take its targets from the ledger and call the guard, S3 adds the one guard call (file named when D2's PR lands). **Owner-loaded models are left alone and the hold message is shown** (PG ruling 3): ANZU leaves them running, and the hold text adds `LM Studio's model "<id>" is still resident because you loaded it; unload it from the model menu to give the render the whole GPU.` using the existing explicit Unload (RFC-0244 inventory is read-only; ANZU stops no other program).

**Respawn after the run (a background path).** The watcher's next poll sees the busy rule false (`wan_loaded` false, no running `generate` run, ingest model unloaded) (or `not_running`, which includes a studio crash) and clears the hold, publishes the cleared state, and does **nothing else** except the optional respawn below. The next **owner turn** loads on demand through the normal path (origin `owner_turn`, which clears `manually_unloaded`). The optional respawn exists only with **Keep warm ON** (`keep_warm` true in the amendment's proposed names), and it is a **background path** (it runs inside `background_scope()` and is subject to #686's stays-unloaded rule; #686's `load_origin` fails closed, so an unknown origin is also background, and section "Load origin: owner turn vs background" is the citation), so:
- The release records `released_seats`, exactly the seats it released. The respawn asks RFC-0225 `prepare_engine_for` for those seats and nothing else, once, never through a private loader.
- **It is skipped whenever `manually_unloaded` is set**, and whenever the owner pressed Unload (single or all) at any time during the hold or between the release and the run's end: S3 hooks the two unload routes in `api/model.py` (`studio_hold.note_owner_unload()`), which drops the seats from `released_seats` and records `respawn_cancelled` even when T3 answers 409 "Nothing to unload" because the hold already released everything. The Unload answer then names the studio: `Nothing to unload: ANZU's models were released for the Black Grid Studio render. Keep warm will not reload them afterwards because you pressed Unload; your next request loads them again.`
- The respawn **never clears `manually_unloaded`** and the hold never sets it. Only an explicit Load or an owner turn clears it. Under `reflex_only` there is no respawn at all.
- ANZU-originated Ollama warms after it use the amendment's `keep_alive` rule (`"-1"` when on, `f"{idle_unload_seconds}s"` when off). With Keep warm OFF (default, `idle_unload_seconds` 300) there is no preload and the normal idle timer applies to whatever loads next. D2's PR sets the final names; S3 follows them.

### Keep warm × studio × engine mode

| | Keep warm OFF (default; `keep_warm` false, `idle_unload_seconds` 300) | Keep warm ON (`keep_warm` true; no idle timer, Ollama `keep_alive` `"-1"`) |

The chat turn is never silent.


## 5. Network and auth

- **Loopback only (S1).** See §2. Nothing in ANZU listens for, proxies or forwards studio traffic; there is no ANZU route that exposes BGM bytes.
- **Remote use goes through ANZU's existing auth.** A phone or LAN companion reaches the studio only by sending an ANZU task or chat turn. That request is authenticated by `auth.authenticate_request` / `require_owner_private_key` (the owner private key; loopback is the owner console, LAN/companion callers need the key) and by the computer-permission checks, exactly like every other tool. The studio's own port is never published. **PG ruling:** BGM has no auth today and token auth is required in BGM before any non-loopback use, so the connector stays loopback only (S1 guard) and this RFC adds no auth code.
- No studio credential is stored by ANZU in this RFC. If BGM-P3 (future, BGM-side token auth) ships, the token goes in the vault (`vault` / `get_effective_private_key` pattern), never in `settings.json`, and lifting the loopback-only rule needs its own RFC amendment.

## Overall acceptance

- [ ] ANZU can list, create and edit studio projects and entities, upload a book and start ingest, read prompts, runs, takes and the movie status, and start generation, regenerate with remarks, approve and stitch, all through the existing `blackgrid_studio` tool and the existing approval gate (S1, S2).
- [ ] Starting a render, regenerating, stitching, ingesting, approving and deleting need a real `ApprovalGrant` bound to the exact target; reads and small edits do not (S2).
- [ ] The connector talks to loopback only, and a non-loopback URL is rejected by settings and by the client (S1).
- [ ] A paused run frees ANZU's hold exactly when BGM-P1 says `wan_loaded` is false; `bgm-ingest-9b` is never unloaded or given a `keep_alive` by ANZU (S3).
- [ ] Of the legacy ComfyUI actions only `status`, `list_outputs` and `submit_hr_endless` leave the tool, in S2's PR, with working `studio_*` replacements and a reviewer-confirmed no-live-caller grep; `open_workbench`, `open_comfy`, `install` and `start` stay until PG signs off a BGM-side replacement (S2).
- [ ] While a studio run holds the GPU, no ANZU model is loaded by any automatic path and explicit Load is refused with a reason; a run start unloads every ANZU-loaded model through the verified path or the ANZU-started run is refused; the next request respawns on demand (S3).
- [ ] Keep warm ON loses to the studio, then respawns the released seats once as a background path, never after an explicit Unload or an Unload pressed during the hold; `reflex_only` never loads or respawns (S3).
- [ ] No load or warm path (manager choke point, front responder, `ensure_local_ollama`, `ensure_ollama_gpu`, `ensure_lmstudio_gpu`, `ensure_local_lmstudio`) can start a model during a hold, and release, idle unload and `keep_alive` act only on the ANZU ledger (S3).
- [ ] Studio-returned text reaches the model fenced as untrusted data, the contract is validated before any upload, and a non-loopback ingest endpoint refuses upload and ingest (S1, S2).
- [ ] The contract is proven in CI against the pinned `tests/fixtures/bgm/contract.json` and recorded endpoint fixtures (no studio, no BGM token in CI), and by a local live check on VRPC with an explicit skip reason when the studio is down (S1, S5).
- [ ] Real-GPU behaviour on Taco's PC is reported separately as a desktop sign-off (S5).

## Risks

- **BGM is still moving.** #33 and #34 are stacked and open, and P1/P2 stack after #34. Mitigation: the gate, the re-trace at assignment, the contract-check items, recorded fixtures and the pinned contract (which PG refreshes); a drift fails a named test and is fixed in an amendment, not worked around.
- **BGM-P1's final shape is PG's.** Only `wan_loaded`, `active_run`, `paused` and `vram_mb` are fixed; `ingest_llm` and `stitch_uses_gpu` are proposed. If PG's PR differs, only S3's parser, S1's model and the pinned fixture change; the rule "the gate reads one studio answer, keyed on `wan_loaded` and `active_run`, never on run state alone" stays.
- **Owner-loaded models keep VRAM.** Taco's LM Studio 9B is not ANZU-loaded, so ANZU will not unload it (PG ruling 3). The studio does not use it. The hold text says so and offers the existing explicit Unload.
- **Studio hangs while up.** `unknown` defers automatic loads rather than risk the render; explicit owner Load is never blocked by `unknown`. The one confirmed-busy case with no ANZU-side exit is an idle resident `bgm-ingest-9b` (ANZU may not unload the studio's model); its hold text names no run and tells the owner the exit (Black Grid Studio, or `ollama stop bgm-ingest-9b`).
- **#686 and D2 names are not final.** #686's head moved while this RFC was reviewed (unload-all, the load-origin rule, the single Ollama helper); the amendment proposes `keep_warm`, `idle_unload_seconds` and the `keep_alive` values and leaves final names to D2's PR, and T3's `inference/model_release.py` lands in the #682 rework. S3 uses #686's sections by name and re-traces every symbol when the rework and D2's PR land (gating item 3).
- **Shared Ollama.** `bgm-ingest-9b` lives in the same Ollama ANZU may use. The primary protection is that release, idle unload and `keep_alive` act only on the ANZU ledger; `StudioModelGuard` (P1's endpoint and model, plus #686's deny constant) is the second layer, so a P1 outage or a corrupt ledger cannot make ANZU touch it. If D2's path enumerates `/api/ps` generically, S3's ledger-only change is the fix and `test_release_and_keep_alive_act_only_on_anzu_ledger_models_not_other_resident_models` is the proof.
- **Approval fatigue.** Approve-take is gated by design; if Taco wants "approve all ready takes" as one grant, that is an amendment with a bulk target, not a gate bypass.
