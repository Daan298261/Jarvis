### Quality bar

The implement is **multibillion-company grade**. Production-grade UX polish, durable persistence, and fail-closed errors are acceptance, not polish to add later. Preview and Set as default must feel finished: the cloud morphs, the saved list updates, the default badge is the one the owner just set, and a restart shows that same look. A prototype panel, a placeholder figure, a success toast before the server persists, or a look that vanishes on restart is a **fail**.

If the landed implement is below that bar, the notify path is **CoS → Taco**. That path is a review rule written in Acceptance and Notes. It is not an API, a setting, a log line, or any other code path.

### Release stretch

User-facing release wording for this feature is **Anzu 1.0**. Do not brand the stretch as “Jarvis 1.x”. The GitHub repository stays [`Daan298261/Jarvis`](https://github.com/Daan298261/Jarvis). Repo paths and existing `Jarvis` code identifiers stay. This RFC does not rename them.

## Problem

The owner can pick a named persona (RFC-0137) and the figure morphs on the existing orb cloud (RFC-0069). They cannot ask for a **new** presence look. Taco / CoS (2026-09-23) want that look generated by the **local Anzu** model from a text prompt or from an image plus optional text, with one hard limit: **every generated object is composed from the existing flowing orbs**. A mesh, a GLTF, a texture, or a free-form HTML/CSS chrome is not a presence look.

What exists on tip (`c7b2267`), and what it is **not**:

- Shapes register in `frontend/src/presence/renderers/shapes/catalog.ts` through `registerPresenceShape`. `buildFigure(density)` returns `ParticleOrb` samples (`x`, `y`, `z`, `gold`, `light`, `flow`, `size`). `buildField` is an optional layer that swaps; it is not the morph silhouette. Helpers in `figureKit.ts` are `fillSphere`, `ring`, and `pushOrb`. Built-ins include `humanoid_bust`, `energy_core`, `hex_aegis`, and the thirteen RFC-0137 shapes (`stormbird` through `forge_core`).
- Morph is `frontend/src/presence/renderers/morphableOrbCloud.ts`. `uMorph` lerps figure samples 0..1. `HumanoidPresence` calls `morphTo` in the frame loop. A React `key` that includes the shape id pops. Reduced motion snaps (`duration: 0`, `immediate: true`) per RFC-0051.
- `frontend/src/hud/HudChatHome.tsx` sets `shapeId` to `hex_aegis` while the HexStrike suite profile is active, otherwise the active named persona’s `presence_shape_id` (fallback `stormbird` when the named-persona client is absent). That suite override **stays in front**.
- Named personas persist on `AppSettings.named_personas` in `data/settings.json` via `load_settings` / `save_settings` (`backend/app/config.py`). `presentation.avatar_id` remains the RFC-0069 avatar map (`jarvis_base` → `humanoid_bust`). Session modes persist separately and do not set a shape or a voice.
- Local inference is the OpenAI-compatible server at `inference.host` / `inference.port`. Vision attaches only when mmproj is loaded (`InferenceManager` vision). There is no custom-UI job, no orb-composition schema, and no “Add new UI” control.
- Image uploads already have a byte cap: `caps_for_kind("image")` in `backend/app/media/store.py` (default 64 MiB, overridable with `JARVIS_MEDIA_FILE_MAX_BYTES`).

## Decision

Add a **global custom presence preset**: a named look the owner generates, previews on the existing orb cloud, saves, and may set as the launch default. The preset chooses the **figure**. It does not choose who is speaking. Named-persona voice, pitch, rate, and specialist copy stay on RFC-0137. Session modes stay HUD + prompt. While the HexStrike suite profile is active, `shapeId` remains `hex_aegis`. Suite on/off does not change the voice and does not clear the stored preset.

Generation uses the **local Anzu** path: the model already attached at `inference.host` / `inference.port`. That is the product. Screenshot-to-code (image → structured UI) and an MCP tool that does the same job are a **reference approach** for the image step, not a dependency and not a cloud vendor. The model’s output is an **orb composition** (JSON). It is not HTML, CSS, a mesh id, or a GLTF.

**Anzu** here is the local generator. It is not a new persona row, not a new voice pack, and not a new GGUF this RFC downloads.

Phases A–D are sequential parts of **this one RFC**. CoS may queue them as separate implement prompts after this PR merges. This file does not name who implements them.

### Shape precedence

One function, used by the HUD and by tests:

`resolve_presence_shape_id(suite_active, active_preset_shape_id, persona_shape_id) -> str`

1. `suite_active` → `hex_aegis`
2. Else a non-empty `active_preset_shape_id` → that id
3. Else `persona_shape_id` (RFC-0137; `anzu` → `stormbird`)

Switching the speaking persona updates the RFC-0137 voice bind and does **not** clear `active_preset_id`. Clearing the active preset (discard of an unsaved preview, or an explicit clear of the active saved look) morphs back to step 3. Suite off morphs back to step 2 if a preset is active, otherwise step 3.

Morph on the live cloud: `morphTo`, `uMorph` 0→1 over the current non-reduced **1.2s**. Do not remount `PresenceHost` / `HumanoidPresence`. A React `key` that includes the shape id, the preset id, or the job id is a **fail**. Reduced motion snaps.

### Phase A — Spec + data model for custom UI presets

Persist on `AppSettings` as `custom_presence`, a sibling of `named_personas`, in the same `data/settings.json` through `load_settings` / `save_settings`. Do not store the look inside `named_personas.profiles`. Do not write `presentation.avatar_id`. Do not store image bytes in `settings.json`.

`CustomPresenceSettings`:

| Field | Meaning |
| --- | --- |
| `presets` | The saved list. |
| `active_preset_id` | The look on the cloud now. Empty means step 3 of shape precedence (persona figure). |
| `default_preset_id` | The look applied on process start. Empty means no custom default. At most one. |

`CustomPresencePreset`:

| Field | Meaning |
| --- | --- |
| `id` | Stable. Pattern `^cui_[a-f0-9]{12,32}$`. Assigned by the server. Not the owner’s display name. |
| `name` | Display name the owner types when they save. 1–80 characters. Not unique against persona labels; the UI shows it as a custom look, not as a fourteenth persona. |
| `source` | `text_prompt`, `image`, or `text_and_image`. |
| `source_image_ref` | Empty when `source` is `text_prompt`. Otherwise a path **relative to `data_dir()`**, under `custom_ui_uploads/`. |
| `prompt_text` | The owner’s text. Required for `text_prompt`. Optional for image sources. Empty string when omitted. |
| `orb_composition` | Version 1 object below. The only description `buildFigure` may read. |
| `shape_id` | `custom_ui_` + the preset `id`. Registered with `registerPresenceShape`. Must not equal a built-in id. |
| `default` | `true` only when `id == default_preset_id`. |
| `created_at`, `updated_at` | ISO-8601 UTC. |

On read, if `default` flags and `default_preset_id` disagree, `default_preset_id` wins and the flags are rewritten. Unknown preset ids fail the request that names them. A missing `default_preset_id` leaves the persona figure in place.

`orb_composition` version **1**:

```json
{
  "version": 1,
  "orb_color": "#9B1B30",
  "accent_color": "#D4A017",
  "framing": { "yaw": 0.08, "position": [0, 0.06, 0] },
  "layers": [
    {
      "kind": "sphere",
      "count_scale": 1.0,
      "radius": 0.78,
      "y": 0.12,
      "gold": 0.15,
      "light": 1.35,
      "flow": 0.4,
      "size": 1.35,
      "motion": "breathe"
    }
  ]
}
```

Allowed `kind` values, and only these, each compiled to orb samples:

| `kind` | Compiles with |
| --- | --- |
| `sphere` | `fillSphere` |
| `ring` | `ring` (optional `tilt`) |
| `arc` | `pushOrb` along a wing-style arc (the stormbird arc loop is the pattern) |
| `orbit` | `pushOrb` along an ellipse |
| `sparks` | scattered `pushOrb` points |
| `shape_sample` | `buildFigure` of an **already registered** non-custom shape id (`shape_id` on the layer). Allowed ids are the RFC-0069 built-ins and the RFC-0137 roster shapes, including `hex_aegis` **as samples only**. Sampling `hex_aegis` does not activate the suite. |

`shape_sample` may not name `custom_ui_*` (no cycles, no chain of unsaved previews). `motion` is `pulse`, `orbit`, `breathe`, or `static`, and it only changes `flow` / the existing presence-state motion on that cloud. It does not add a renderer.

Colours are `#RRGGBB`. `gold` is 0..1, `light` and `flow` and `size` stay in the ranges `ParticleOrb` already uses. `count_scale` is 0.05..4. A layer list is 1..24 layers. Extra keys that are not in this schema fail validation.

**Reject** the composition if any key or string value (case-insensitive) contains `mesh`, `gltf`, `glb`, `texture`, `material`, `html`, `css`, `silhouette`, or a `kind` outside the table. No mesh ids. No asset paths. No HTML.

`buildFigure` for `shape_id` is a pure function of `orb_composition` and density. `buildField` is omitted. `registerPresenceShape` must **refuse** to replace `humanoid_bust`, `energy_core`, `hex_aegis`, or any RFC-0137 shape id. Today the registry overwrites on id collision; the custom path may not use that overwrite.

### Phase B — Backend generation job via Anzu

New routes, not `/api/named-personas` and not `/api/session-personality`:

- `POST /api/custom-presence/jobs` — body is JSON `{ "prompt_text": "..." }` and/or multipart with an image file plus optional `prompt_text`. At least one of text or image is required.
- `GET /api/custom-presence/jobs/{id}` — job record.

Job statuses: `queued`, `running`, `succeeded`, `failed`, `rejected`.

A succeeded job returns `orb_composition` and a **temporary** registered shape id `custom_ui_preview_<job_id>`. That id lives until save or discard. It is not a preset yet.

**Local Anzu.** The job calls the loaded local inference endpoint. The request always includes the locked constraint below, ahead of the owner’s prompt, where the owner cannot remove it. If the endpoint is not loaded, connect fails, or the call errors, status is `failed` with `error.code` `model_unavailable`. The response has no composition and no shape id. Do not synthesize a placeholder look. Do not return HTTP 200 with an empty success. A dev flag such as `JARVIS_SKIP_MODEL` is not a product success path.

**Image.** Accept the same image types the media store already accepts (`image/jpeg`, `png`, `webp`, and the other `_IMAGE_TYPES`). Reject oversize with the existing image cap (`caps_for_kind("image")`), HTTP 413, no job. Store accepted bytes under `data_dir() / "custom_ui_uploads" /` and set `source_image_ref` to the relative path. Pass the image to Anzu **only when vision is loaded** (mmproj attached). If an image was sent and vision is not loaded, status is `failed` with `vision_unavailable`. Do not drop the image and succeed as text-only. Text-only jobs do not require vision.

**Reference, not a vendor.** Screenshot-to-code is the pattern “screenshot in, structured UI out.” An MCP with that pattern may be cited in comments. The product call is local Anzu. Do not require a cloud screenshot-to-code SaaS, an API key, or a specific MCP server. If a later ticket wires an MCP, that MCP’s output still has to be this `orb_composition` and still has to pass the Phase A validator. HTML or CSS from that tool is `rejected`.

**Constraint** (exact string the job sends; tests assert it is present on every model call, including the regenerate):

```
Return only JSON orb_composition version 1. Every generated object is composed of flowing orbs using kinds sphere, ring, arc, orbit, sparks, or shape_sample of an already registered presence shape. Do not return mesh, glTF, GLB, texture, material, HTML, or CSS.
```

Parse the model text as JSON. Run the Phase A validator. On failure, **regenerate once** with the validator errors appended. A second failure sets status `rejected` with `constraint_rejected` and does not register a shape and does not write a preset. A model reply of `{"rejected": true, "reason": "..."}` is `rejected` immediately (no second call).

`invalid_input` when both text and image are missing (HTTP 400, no job record required).

### Phase C — Portal Add new UI flow

On the Appearance / named-persona surface, add a button labelled **Add new UI**. Place it in `AppearanceSettingsPane` **beside** `NamedPersonaControls`, `SessionPersonalityControls`, and the HexStrike control. Do not replace them.

The button opens one modal wizard:

1. **Input.** A text area for the look, and an image file input. The owner may send text, or an image, or both. Copy states that the result is built from the flowing orbs.
2. **Generate.** `POST` the job. Show `queued` / `running`. Show `model_unavailable`, `vision_unavailable`, and `constraint_rejected` as errors with the server message. Do not show a fake preview on those codes.
3. **Preview.** On `succeeded`, morph the **existing** orb cloud to `custom_ui_preview_<job_id>` through `uMorph`. Do not mount a second `HumanoidPresence`, a second canvas, or a second WebGL context. If the shell is Classic (`requestedPresence` `none`) and the cloud is not mounted, say that preview needs Humanoid HUD or Particle bust. Do not spawn a renderer to paper over that, and do not change the shell unless the owner picks that presence mode with the existing Appearance controls.
4. **Actions** (finished, not a prototype — the list, the badge, and the cloud agree before the wizard says it is done):
   - **Set as default** — save if the preview is not saved yet (name required; default the name from the first 48 characters of `prompt_text`, or `Custom look` when the prompt is empty), set `default` / `default_preset_id` / `active_preset_id` to this preset, clear `default` on every other preset, register `custom_ui_<preset id>`, morph to it, unregister the preview id.
   - **Save as named custom UI** — same persist, owner-supplied name, **without** changing `default_preset_id`. It becomes `active_preset_id` so the look they kept stays on the cloud until they discard or pick another.
   - **Discard** — unregister `custom_ui_preview_*`, morph back to the shape precedence **before** the wizard opened, delete the unsaved preview. Do not delete presets already in `presets`.

Reduced motion snaps the preview morph. No remount key on the preview shape id.

List saved presets on the same pane (name, default badge, delete). Delete of the active or default preset clears that id and morphs back to the persona figure (or to `hex_aegis` if the suite is active). This list is additional. It is not the persona `<select>`.

### Phase D — Persistence + load default on launch + tests

Process start, after the existing `reapply_stored_main_persona` path, loads `custom_presence`. If `default_preset_id` matches a preset, register that preset’s `shape_id` from its stored `orb_composition` and set `active_preset_id` to it when `active_preset_id` is empty. Do not call `set_active_voice_profile_id` from this path. HexStrike still wins at render time via shape precedence, so a default preset does not hide `hex_aegis` while the suite is on.

Restart with a stored default shows that custom figure (suite off) without asking the model again. The composition is the source of truth; generation does not re-run on launch.

Tests live in `tests/test_rfc0138_custom_presence.py`. They assert. They do not `pytest.skip` and they do not treat a missing model as success.

- Validator accepts each allowed `kind`, including `shape_sample` of `stormbird`, and rejects `mesh`, `gltf`, `glb`, `texture`, `html`, `css`, an unknown `kind`, and `shape_sample` of a `custom_ui_*` id.
- The job builder puts the locked constraint string on every model call.
- A scripted model provider (the only stub, and only inside pytest, same pattern as other inference tests) that returns a valid composition yields `succeeded`, a preview shape id, and a composition that passes the validator.
- A scripted provider that returns a mesh / GLTF / HTML payload yields `rejected` / `constraint_rejected` after the one regenerate, with no preset written.
- When the provider raises unavailable, the job is `failed` / `model_unavailable` with no composition. Product code has no branch that invents a composition in that case.
- An image job while vision is off is `vision_unavailable` and does not call the text model as if the image were absent.
- Set as default persists exactly one `default: true`, and a fresh `load_settings` plus the launch reapply selects that `shape_id`.
- `PUT /api/named-personas` still binds voice per RFC-0137 and does not clear `active_preset_id`.
- `PUT /api/session-personality` does not change `custom_presence` and does not change `shapeId`.
- `resolve_presence_shape_id(True, "<custom>", "stormbird")` is `hex_aegis`.

`python3 -m pytest` includes this module. `npm --prefix frontend run build` and `npm --prefix frontend run lint` when the portal files land. Live morph on a GPU and a real Anzu vision pass are Windows desktop sign-off. Cloud pytest uses the scripted provider only.

### What a failed implement looks like

- Removing, hiding, or collapsing session modes, `VoiceProfilePicker`, Appearance, `NamedPersonaControls`, the 13-persona roster, HexStrike / Daybreak, or the morphable orb path.
- Replacing those controls with **Add new UI**.
- A fourteenth persona row, a new voice pack, or a custom look that calls `set_active_voice_profile_id`.
- Binding the custom figure to the speaking persona so a persona change drops the owner’s look.
- Clearing `hex_aegis` while the suite is active, or changing voice when the suite toggles.
- A second presence renderer, a second canvas, or a React `key` on the shape, preset, or job id.
- `buildFigure` that reads a mesh, GLTF, texture, HTML, or CSS, or a registry overwrite of a built-in shape id.
- HTTP 200 or a saved preset when Anzu is unavailable, when vision is required and missing, or when the validator rejected the reply.
- A cloud screenshot-to-code SaaS or a required MCP as the only generation path.
- A merged RFC-0104 tree, or product code in the specs PR.
- Prototype UX: a mock preview, a control that claims Set as default before `settings.json` has the preset, a soft-fail that stores a partial look, or copy that brands this stretch “Jarvis 1.x”.
- A code path whose job is to notify Taco. The quality escalate is **CoS → Taco** in review, written here, not implemented.

## Acceptance criteria

- [ ] **Data model.** Presets persist on `AppSettings.custom_presence` in `data/settings.json` with stable `id`, display `name`, `source`, optional `source_image_ref` and `prompt_text`, `orb_composition`, `default`, and timestamps. The look is global: it is not stored on a named-persona profile and it does not follow who is speaking. `presentation.avatar_id` is unchanged.
- [ ] **Orb constraint.** Validation allows only `sphere`, `ring`, `arc`, `orbit`, `sparks`, and `shape_sample` of a registered non-custom shape. Mesh, GLTF/GLB, texture, material, HTML, and CSS are rejected. Custom shapes do not overwrite built-in shape ids.
- [ ] **Generation job.** `POST /api/custom-presence/jobs` accepts text and/or image+text, injects the locked orb-only constraint on every call, regenerates once on a bad payload, and returns status plus a composition and a temporary shape id only when validation passed.
- [ ] **Fail closed.** Anzu unavailable → `model_unavailable`, no composition, no preset. Image without loaded vision → `vision_unavailable`, and the image is not discarded into a text-only success.
- [ ] **Portal flow.** **Add new UI** sits beside the existing Appearance / persona controls. The wizard takes text and/or an image, shows job status, and offers Set as default, Save as named custom UI, and Discard.
- [ ] **Preview.** Succeeded jobs morph the existing orb cloud through `registerPresenceShape` and `uMorph`. No second renderer. No remount key on the shape id. Reduced motion snaps.
- [ ] **Set default + named save.** Set as default stores exactly one default and makes it the active look. Save as named writes the preset under the owner’s name. Discard drops only the unsaved preview and morphs back.
- [ ] **Launch reload.** Process start re-registers the default preset’s `buildFigure` from the stored composition and selects it when the suite is off, without calling the model again. Suite on still renders `hex_aegis`.
- [ ] **Keep existing UI.** Session modes, `VoiceProfilePicker`, Appearance, the 13-persona roster, HexStrike / Daybreak, and the morphable orb path still work. Persona voice bind and session-mode behaviour are unchanged. No new voice packs. RFC-0104 stays unmerged.
- [ ] **Tests.** `tests/test_rfc0138_custom_presence.py` covers the bullets above. Pytest may script the model provider; product code must not. No `pytest.skip` and no soft-fail on `model_unavailable`. `python3 -m pytest`. Portal implement also runs `npm --prefix frontend run build` and `npm --prefix frontend run lint`.
- [ ] **Quality bar.** The wizard, errors, preview morph, Set as default, named save, and launch reload are production-grade: durable persistence, fail-closed errors with no stubs or soft-fail, and a preview / default that feel finished. Subpar implement is not accepted on review. The notify path is **CoS → Taco**. That path is this review rule, not a code path.
- [ ] **Anzu 1.0 stretch.** User-facing release wording this feature adds says **Anzu 1.0**, not “Jarvis 1.x”. The repo stays `Daan298261/Jarvis`. Existing paths and `Jarvis` identifiers stay.

Live Anzu vision and a GPU capture of the preview morph are Windows desktop sign-off. Sign-off includes the quality bar: the flow looks finished, the default survives restart, and failures stay fail-closed. A miss goes **CoS → Taco**.
